# AI와 함께 이 프로젝트를 고쳐 쓰는 가이드

[English](ai-adaptation-guide.md) | **한국어**

> 이 문서는 **사람과 인공지능이 함께 읽도록** 썼습니다. 인공지능에게 이 저장소를 고쳐 달라고
> 할 때 이 문서를 함께 건네 주십시오. 인공지능은 이 문서에서 고칠 순서와 지켜야 할 약속을 읽고,
> 사람은 인공지능이 한 일을 무엇으로 확인할지 알 수 있습니다.

예전에는 업무 도구가 필요하면 처음부터 손수 만들어야 했습니다. 이제는 이미 있는 예제를
인공지능과 함께 내 일에 맞게 고쳐 쓸 수 있습니다. 이 프로젝트는 도서관을 보기로 삼아
**다국어, 3D 시각화, 물류·재고 흐름, 회원·권한 관리**를 담은 출발점입니다. 목표는 작거나 중간
규모의 업무 데이터를 다루는 많은 사람이 복잡한 인프라를 들이기 전에, 웹 앱과 Excel, Microsoft
Graph를 엮어 쓸모 있는 결과를 얻도록 돕는 것입니다.

## 무엇을 바꿀지 먼저 정하기

도서관 낱말만 바꾸지 말고, 다음 항목을 한 문장씩 정합니다.

1. 관리 대상: 도서, 장비, 소모품, 공간, 차량, 문서 가운데 무엇인가?
2. 핵심 상태: 예) `received`, `ready`, `checked_out`, `due`, `returned`, `outbound`
3. 역할: 조회자, 회원·신청자, 관리자·승인자
4. 데이터 규모와 동시 사용자 수
5. 남겨야 하는 이력과 업무 규칙
6. Excel을 원본으로 계속 쓸지, 규모가 커지면 다른 저장소로 옮길지

도메인이 작고 함께 일하는 사람들이 Excel로 내용을 확인해야 한다면 이 프로젝트의 단일 workbook
구조가 잘 맞습니다. 많은 사용자가 동시에 쓰거나 엄격한 트랜잭션이 필요하다면, `LibraryRepository`
경계는 그대로 두고 adapter를 데이터베이스로 바꾸는 방안을 인공지능에게 요청하십시오.

## 파일별로 고치는 순서

| 단계 | 파일·영역 | AI에게 맡길 일 |
| --- | --- | --- |
| 1 | `src/lib/domain.ts` | 엔티티, 역할, 상태 전이, Zod 스키마 변경 |
| 2 | `src/lib/transitions.ts` | 업무 규칙, 승인·반납·출고 전이와 권한 검사 |
| 3 | `src/lib/demo-data.ts`, `scripts/generate-workbook.ts` | 새 샘플 데이터와 Excel 표 생성 |
| 4 | `src/lib/repositories/` | 기존 계약에 맞춘 local/Excel adapter 유지 또는 확장 |
| 5 | `src/app/api/` | 새 action의 검증과 서버 쪽 RBAC 연결 |
| 6 | `src/components/`, `src/lib/i18n.ts`, `src/lib/journey.ts` | 목록·상세·대시보드 화면, 다국어 문자열, 이용방법 변경 |
| 7 | `*.test.ts`, `*.test.tsx` | 상태 전이, 권한, 메뉴 노출, 화면 회귀 검증 |

`src/lib/journey.ts`의 이용방법은 처음 온 사람에게 기능마다 쓰는 법을 두 언어로 알려 줍니다.
도메인을 바꾸면(책을 장비로, 대출을 체크아웃으로) 이 설명도 함께 고치십시오. 안내의 각 단계는
`data-tour` 속성으로 화면 요소를 찾으므로, 그 부분을 옮기거나 새로 짤 때 속성을 남겨 두고, 기능을
더하면 단계도 하나 더하십시오.

처음에는 `domain.ts`와 workbook 생성기를 함께 고치고 테스트로 계약을 굳힌 뒤, 화면은 그다음에
바꾸는 편이 안전합니다. 여러 계층을 한꺼번에 만들어 달라고 하면 문제가 생겼을 때 원인을 찾기
어렵습니다.

## Excel과 Microsoft Graph를 데이터 원본으로 쓸 때 지킬 약속

- 표 이름과 열 이름은 계약입니다. 의미 있는 변경이 있을 때마다 `schemaVersion`도 함께 살핍니다.
- 모든 행에 바뀌지 않고 겹치지 않는 `id`와, 낙관적 동시성을 위한 `version`을 둡니다.
- 화면이나 인공지능이 만든 값을 그대로 Graph로 보내지 말고, 서버에서 Zod로 다시 검증합니다.
- 역할(role)에 따른 권한은 브라우저에서 메뉴를 숨기는 것만으로 지킬 수 없습니다. API가 action마다 권한을 다시
  검사합니다.
- 기존 workbook에 사용자가 직접 더한 열은 읽고 쓰는 동안 그대로 남아야 합니다.
- secret, access token, Graph ID, 실제 회원 정보는 프롬프트에도 소스에도 넣지 않습니다.
- Excel은 함께 보고 고치기 좋고 작거나 중간 규모에 알맞지만, 데이터베이스 수준의 트랜잭션은
  제공하지 않습니다.

Graph 모드 설정과 workbook 표 계약은 [README](../README.ko.md)의 실행 절차를 기준으로 합니다.

## 인공지능에게 건넬 수 있는 요청문

### 1. 도메인 바꾸기

```text
이 저장소를 도서관 앱에서 사내 장비 대여 앱으로 바꾼다.
먼저 src/lib/domain.ts와 Workbook 표 계약만 살펴보고 변경 계획을 내라.
기존 엔티티는 Books→Assets, Loans→Checkouts처럼 짝지어 옮기고,
received, ready, checked_out, due, returned, outbound 상태를 제안하라.
파일을 고치기 전에 id/version, 관계, 서버 RBAC, Excel 호환성을 어떻게 지킬지 설명하라.
```

### 2. 작은 업무 규칙 더하기

```text
대여 중인 자산은 삭제할 수 없고, overdue 상태는 member가 승인 없이 바꿀 수 없게 한다.
먼저 src/lib/transitions.test.ts에 실패하는 테스트를 더한 뒤, 그 테스트를 통과하는 만큼만 구현하라.
사용자가 아직 커밋하지 않은 변경과, Excel에 사용자가 더한 열을 보존하는 로직은 건드리지 마라.
```

### 3. 다국어 화면 더하기

```text
새 자산 종류와 상태만 한국어/영어로 더한다.
src/lib/i18n.ts의 키 구조를 따르고 문자열을 코드에 직접 쓰지 마라.
기존 화면 테스트를 고치고, 한국어 전환, html lang, 관리자 메뉴 노출 여부를 검증하라.
```

### 4. 3D 표시를 다른 자산에 맞추기

```text
서가 시각화를 창고 선반 위치로 바꾼다.
도메인 필드와 배치 계산을 먼저 떼어 내고, 실제 데이터가 없을 때에도
3D 대신 접근 가능한 목록 정보를 보여 주도록 유지하라.
```

## 인공지능에게 맡길 일을 작게 나누는 방법

좋은 작업 단위는 "계약 → 구현 → 테스트 → 설명"을 한 번에 확인할 수 있는 크기입니다.

1. `git status`와 diff를 읽고, 사용자가 해 둔 변경을 어떻게 지킬지 정한다.
2. 한 기능의 상태·역할·표 계약부터 정리한다.
3. 실패하는 단위 테스트나 화면 테스트를 더한다.
4. 도메인, 서버, 화면 순서로 꼭 필요한 만큼만 고친다.
5. `npm run typecheck`, `npm run lint`, 해당 `npm test`, `npm run build`를 실행한다.
6. workbook 스키마가 바뀌었으면 새로 만든 파일과 표 이름·열을 확인한다.

단계마다 인공지능에게 다음 약속을 되풀이해 알려 주는 것이 좋습니다.

> 작업 트리에 있는 관련 없는 변경을 덮어쓰지 말고, 관련 파일만 고쳐라. 보안·권한 검사는
> 브라우저뿐 아니라 서버에도 넣고, 실제 데이터나 secret을 코드에 박아 넣지 마라.
> 고친 뒤에는 실행한 테스트·빌드 명령과 결과, 아직 확실하지 않은 점을 보고하라.

## 정의를 마쳤는지 확인하는 점검표

- [ ] 모든 엔티티에 고유한 `id`와 `version`이 있다.
- [ ] 상태 전이마다 허용하는 역할과 앞선 상태가 정해져 있다.
- [ ] 관리자 메뉴와 API 권한이 모두 역할을 따르며, 회원 화면에는 관리자 링크가 없다.
- [ ] Excel 표와 demo 데이터가 같은 계약을 쓴다.
- [ ] 기존 workbook의 선택 열과 사용자가 더한 열이 보존된다.
- [ ] 다국어 화면에 빠진 문자열이나 코드에 직접 쓴 영어가 없다.
- [ ] 3D나 시각화가 실패해도 목록과 상태 정보로 일을 이어 갈 수 있다.
- [ ] `src/lib/journey.ts`의 안내 단계가 모두 `data-tour` 요소를 가리키고, 바뀐 도메인을 설명한다.
- [ ] 입고·등록, 대출·체크아웃, 만기·연체, 반납·출고 테스트가 있다.
- [ ] 실제 Graph 자격 증명 없이 할 수 있는 검증과, 운영 자격 증명이 있어야 하는 검증이 나뉘어 있다.

## 이 예제가 잘 맞는 곳

- 사용자가 많지 않고 Excel로 함께 고치고 확인하는 경험이 중요한 업무
- 등록, 신청, 승인, 대출, 반납, 만기, 위치처럼 상태가 또렷하게 나뉘는 흐름
- 인공지능과 주고받으며 요구 사항을 좁혀 가고 화면과 규칙을 검증하려는 팀
- PostgreSQL이나 ERP를 들이기 전에 실제 업무 흐름을 먼저 시험해 보려는 프로젝트

사용량과 동시 사용이 늘면 화면과 도메인 규칙은 그대로 두고, repository adapter를 트랜잭션을
지원하는 저장소로 바꾸십시오. Excel은 언제까지나 써야 하는 기본값이 아니라, **적은 비용으로 시작해
실제 쓰임새를 확인할 수 있는 데이터 원본**입니다.
