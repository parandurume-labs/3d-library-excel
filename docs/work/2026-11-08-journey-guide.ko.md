## 요청 (원문)

> 해당 프로젝트에 첫 사용자들을 위한 journey
>
> journey guide를 추가해서 각 기능별 하이라이트 및 설명서를 통해 기능별 사용을 안내해주면 좋겟어요.
>
> User Journey Guide 생성한 다음 문서들도 적절히 업데이트 해주세요.

## Architect

- 요구 재진술:
  1. 처음 앱을 연 사람이 기능을 차례로 익히도록 길을 안내한다.
  2. 안내는 실제 화면에서 기능을 밝혀 보여 주는 하이라이트와, 기능마다 쓰는 법을 적은 설명서로 이루어진다.
  3. 만든 뒤 README와 가이드 문서를 함께 고친다.
- 결정·불변 규칙 충돌: 없음. Workbook 표 계약, API, 저장소 계약, 서버 RBAC는 바꾸지 않는다. 새 npm 의존성 없음(오버레이를 직접 만듦).
- 화면 설계:
  - 첫 방문 카드: 홈 제목 아래 "처음 오셨나요?" 카드. 시작하거나 '다음에 보기'를 누르면 `localStorage`의 `durume-journey-v1`에 기록해 다시 띄우지 않는다. 저장소가 막힌 브라우저에서는 다음에 다시 뜰 뿐 오류는 나지 않는다.
  - 둘러보기(`journey-tour.tsx`): 화면을 어둡게 하고 대상 요소 둘레만 밝힌다. 어둡게 한 층은 클릭을 막지 않아서, 읽으면서 바로 써 볼 수 있다. 카드는 대상 아래, 안 되면 위, 둘 다 안 되면 오른쪽 아래 구석에 둔다. 폭 640px 미만에서는 화면 아래에 붙이고 대상을 위쪽으로 올린다.
  - 단계 정의(`src/lib/journey.ts`): 15단계, 7묶음. 단계마다 보여 줄 탭과 `data-tour` 대상, 관리자 전용·데모 전용 여부를 적는다. 회원에게는 관리자 단계 3개를 빼고, Graph 모드에서는 역할 바꾸기 단계를 뺀다.
  - 역할 이어 가기: 데모의 회원이 역할 단계에서 '관리자 화면으로 바꾸기'를 누르면 관리자 데이터를 다시 불러온 뒤 사서실 단계가 이어진다. 둘러보기 중에 회원으로 돌아가 단계가 사라지면, 새 데이터를 다 받은 뒤 다음 단계로 넘어간다(`nextAvailableStep`).
  - 기능 설명서(`journey-guide-page.tsx`): 사이드바 아래쪽 '이용방법' 탭. 기능 13개를 묶음별로 보여 주고, 기능마다 '화면에서 보기' 버튼으로 그 단계부터 둘러보기를 연다. 회원이 관리자 기능을 누르면 데모에서는 관리자 화면으로 바꾼 뒤 보여 주고, Graph 모드에서는 버튼을 끈다.
  - 접근성: 카드는 `role="dialog"`(모달 아님), 단계마다 제목으로 초점을 옮기고, 닫으면 연 버튼으로 돌려준다. 연 버튼이 사라졌으면 사이드바의 '이용방법', 그것도 안 보이면 화면 제목으로 보낸다. Esc로 닫고, 카드 안에서 좌우 화살표로 오간다. 둘러보기가 열려 있으면 앱의 Esc(3D 한 걸음 물러나기, 상세 닫기)는 쉰다. 움직임 줄이기 설정이면 부드러운 스크롤과 전환을 끈다.
- 사실 확인: 안내 문구의 주장은 코드와 대조했다. 알림 숫자(수령 가능한 예약 + 신청 중 대출 + 연체), 검색 대상(원제·한국어 제목·저자·DDC·KDC), 검색하면 서가 둘러보기 탭으로 옮김, 위치 버튼이 그 관의 첫 서가를 고름, 자기 역할 선택 상자 비활성, 대출 중인 책 삭제 차단(`deleteBook` 문구).
- 검증 계획: vitest(단계 필터, 둘러보기 흐름, 관리자 전환, 한국어 설명서), tsc, eslint, 교정 스크립트, 브라우저(1440×900, 390×844).

## 후속 변경 (사용자 요청)

> Journey Tour 와 이용방법 으로 해주고 기존 내용은 그래도 둬도 될 것 같습니다. 버전은 바뀌어야 할 것 같은데요. 1.1.0 는 최소한 되어야 할 것 같아요.
>
> About & guide는 About Project로 해주세요.
>
> 소개와 가이드 -> 프로젝트 안내

- 새 메뉴 이름: 영어 "Journey guide" → "Journey Tour", 한국어 '이용 안내' → '이용방법'. 사이드바 메뉴, 설명서 머리 글자, 첫·끝 단계 문구, README 두 언어, AI 적응 가이드 두 언어, 테스트를 함께 고쳤다. 코드 식별자와 파일 이름(`journey-guide-page.tsx`, `guide` 탭, `durume-journey-v1` 키)은 그대로 둔다.
- 기존 메뉴 이름: 영어 "About & guide" → "About Project", 한국어 '소개와 가이드' → '프로젝트 안내'(`i18n.ts`의 `helpGuides`, README 두 언어, 테스트, 주석). 이전 작업 기록(2026-11-07)은 당시 기록이라 고치지 않았다.
- 버전: `package.json`, `package-lock.json`을 1.0.0 → 1.1.0으로 올림(새 기능이므로 minor). `npm version 1.1.0 --no-git-tag-version`으로 바꿔 태그는 만들지 않았다.
- 표기: '이용방법'은 사용자가 정한 메뉴 이름이라 붙여 쓴다. 맞춤법 원칙대로라면 '이용 방법'이다.
- 재검사: `npx vitest run` 8개 파일 51개 통과, `npx tsc --noEmit` 0, `npx eslint .` 0, `scan.mjs` 후보 0건, `git diff --check` 이상 없음.
- 프로덕션 빌드는 다시 확인하지 못했다. 개발 서버가 켜진 채로 `npm run build`를 돌려 `.next`가 겹쳤고, "no direct app page entry found for /_not-found" 오류로 멈췄다. 코드 문제가 아니라 캐시 충돌이다. 그 뒤 작업 트리를 다른 폴더에 복사해 `next build`를 돌렸고 통과했다.
