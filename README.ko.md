Microsoft MVP로서 제 목표는 두 가지입니다. 하나는 기술의 혜택이 몇몇 사람에게 머물지 않고
더 많은 사람에게 두루 퍼지게 하는 것이고, 다른 하나는 기술이 누구도 밀려나지 않고 함께
어우러지는 포용적인 세상을 만드는 데 보탬이 되게 하는 것입니다. 배운 것을 나누는 일이 MVP의

**인공지능은 누가 다루고 어떻게 쓰느냐에 따라 달라집니다.** 몇몇 사람의 손에만 머물면 격차를
더 벌리고, 많은 사람의 손에 닿으면 기회를 넓힙니다. 큰 회사나 전문 개발팀이 아니어도 학교와
마을 도서관, 작은 단체와 동네 일터가 인공지능과 함께 자기 일에 꼭 맞는 도구를 만들 수 있어야

이 저장소는 그 믿음을 손에 잡히는 결과물로 옮겨 본 것입니다. 더 많은 사람이 더 많은 기회와
혜택을 누리는 풍요로운 세상으로 가는 작은 시작이 되기를 바랍니다.

## 이제는 손수 짜지 않고 인공지능과 함께 고쳐 씁니다

예전에는 쓸 만한 업무 도구를 가지려면 처음부터 직접 만들거나 값비싼 제품을 사야 했습니다.
이제는 인공지능과 이야기를 나누며 이미 있는 예제를 내 일에 맞게 고쳐 쓸 수 있습니다. 다만
인공지능에게 "알아서 만들어 줘"라고만 하면 엉뚱한 곳을 건드리거나 보안 판단을 놓치기 쉽습니다.

그래서 이 저장소에는 사람이 읽는 설명서와 함께 **인공지능을 위한 가이드**를 따로 두었습니다.

- [AI와 함께 이 프로젝트를 고쳐 쓰는 가이드](docs/ai-adaptation-guide.ko.md): 인공지능에게 그대로
  건넬 수 있는 요청문, 고칠 파일의 순서, 결과를 확인하는 기준, 인공지능에게 맡기면 안 되는
  보안 판단을 담았습니다.
- [작업 기록](docs/work/): 인공지능과 함께 설계, 조사, 구현, 독립 검수를 거쳐 기능을 더해 온
  과정을 그대로 남겼습니다. 다른 사람이나 다른 인공지능이 이어받아 일할 수 있습니다.

코드를 깊이 알지 못해도 이 가이드를 인공지능에게 함께 건네면, 도서관 앱을 장비 대여나 교구 관리,
공간 예약 앱으로 한 걸음씩 바꿔 나갈 수 있습니다. 앱 안의 **프로젝트 안내** 메뉴에서도 같은
내용을 볼 수 있습니다.

## AI로 만드는 작고 실용적인 데이터 관리 앱

이 저장소는 **도서관만을 위한 제품이 아닙니다.** 누구나 자기 일에 맞게 가져다 쓸 수 있는
애플리케이션 예제입니다. Next.js와 Three.js로 만든 도서관 화면에 업무 앱이 흔히 갖추는 기능을
함께 담았습니다.

- **다국어**: 한국어·영어 화면과 데이터 표시
- **3D 시각화**: 공간, 위치, 자산 상태를 한눈에 둘러보기
- **물류·재고 흐름**: 등록·입고, 대출·체크아웃, 예약, 반납 예정일과 연체, 반납·출고 처리
- **회원·권한 관리**: 역할에 따라 다른 화면, 승인 절차, 개인 현황과 운영 업무의 분리

무엇보다 이 프로젝트는 큰 데이터베이스부터 들이지 않아도 **인공지능과 대화하며 작거나 중간
규모의 데이터 관리 앱을 만들 수 있다**는 것을 보여 주는 실전 예제입니다. OneDrive에 있는
**Excel workbook 하나를 데이터 원본으로 쓰고**, Microsoft Graph로 인증된 읽기·쓰기를 연결합니다.
도메인 이름과 Excel 표만 바꾸면 도구·장비·공간 예약, 사내 물품 대여, 교육 자료 관리 등에 맞춰
쓸 수 있습니다.

Graph/Excel 모드에서는 Excel workbook 하나가 원본(source of truth)이며, SharePoint 목록이나 로컬
DB에 함께 기록하지 않습니다. 자격 증명이 없으면 합성 데이터만 쓰는 로컬 데모 모드로 모든 사용자
흐름을 살펴볼 수 있습니다.

## 이 예제에 담긴, 다시 쓸 수 있는 기능

- 3D 서가 회전·확대, 서가·위치 선택, 검색과 분류 필터
- 3D 도서관 화면: 서가 앞으로 다가가 보기, 전체 보기로 돌아오기, 책에 마우스를 올리면 보이는 정보
- 처음 온 사람을 위한 이용방법: 실제 화면에서 기능을 하나씩 짚어 보여 주는 둘러보기, 기능마다 '화면에서 보기' 버튼이 달린 기능 설명서
- 한국어/영어 화면 전환과 언어별 데이터 표시
- DDC/KDC 표시 전환, 상세 패널을 연 채로 3D 서가에서 책 위치 찾기
- 등록(입고), 대출 신청, 예약, 반납 신청, 반납 예정일·연체 표시와 알림
- 회원의 개인 대출·예약 현황, 관리자의 승인과 반납(출고·회수) 처리
- 도서·자산 등록·수정·삭제·배치와 회원·역할 관리
- Microsoft Entra delegated OAuth와 Microsoft Graph로 하는 Excel 표 읽기·쓰기
- 안정 ID와 버전으로 하는 낙관적 동시성 검사, 서버 쪽 역할 기반 접근 제어
- 작은 도메인 모델을 인공지능으로 넓혀 갈 때 검증 기준으로 삼을 수 있는 520권짜리 합성 Excel workbook

## 빠른 시작: 자격 증명 없이 로컬 데모 실행

Node.js 20 이상과 npm이 있어야 합니다.

```powershell
npm install
Copy-Item .env.example .env.local
# .env.local의 DATA_MODE=demo 확인
npm run dev
```

`http://localhost:3000`을 엽니다. 화면 위쪽에 `LOCAL DEMO DATA`(한국어 화면에서는 `로컬 데모 데이터`)
표시가 보여야 합니다.

- 위쪽 사용자 선택기에서 `Member view`(회원 화면)와 `Admin view`(관리자 화면)를 바꿔 볼 수 있습니다.
- 기본 회원 계정: 안정 ID `user-demo-member`, 이름 `Demo Member`
- 기본 관리자 계정: 안정 ID `user-demo-admin`, 이름 `Demo Librarian`
- 관리자 메뉴와 `Admin desk`(사서실)는 `Admin view`에서만 보입니다. 회원 화면에는 링크조차 나타나지 않습니다.
- 데모 이메일은 실제 계정이 아닌 `*.example.invalid` 주소입니다.
- 사이드바 아래쪽의 `About Project`(프로젝트 안내)에서 이 프로젝트를 만든 까닭과 기술 스택, 인공지능을 위한 가이드를 볼 수 있습니다.

### 처음 오셨다면: 이용방법

처음 들어오면 홈 화면 위쪽에 **처음 오셨나요?** 카드가 뜨고, 2분짜리 둘러보기를 권합니다. 둘러보기는
화면을 어둡게 한 뒤 기능을 하나씩 짚어 보여 주며 쓰는 법을 알려 줍니다. 필요한 화면으로는
알아서 옮겨 가며, 언제든 앞뒤로 오가거나 닫을(Esc) 수 있습니다.

| 순서 | 묶음 | 짚어 주는 기능 |
| --- | --- | --- |
| 1 | 책 찾기 | 검색, 3D 평면도, 주제·DDC/KDC 필터, 도서 카드와 상세 정보 |
| 2 | 3D 도서관 걷기 | 서가 앞에 서서 책 찾기 |
| 3 | 빌리고 챙기기 | 내 서재(대출, 반납 예정일, 반납 신청, 예약)와 알림 |
| 4 | 화면 맞추기 | 언어 바꾸기, 데모에서는 회원·관리자 화면 바꾸기 |
| 5 | 사서실 일 | 승인과 반납 처리, 회원과 역할, 장서와 서가 배치(관리자만) |
| 6 | 내 일에 맞게 | 인공지능과 함께 앱을 고쳐 쓰는 가이드 |

- 데모의 회원 화면에서는 역할 단계의 **관리자 화면으로 바꾸기**를 누르면 사서실 안내가 이어집니다.
- 사이드바 아래쪽의 **이용방법**은 기능 설명서입니다. 기능마다 쓰는 법을 짧게 적고, **화면에서 보기**
  버튼으로 그 기능을 바로 짚어 보여 줍니다. 둘러보기를 처음부터 다시 시작할 수도 있습니다.
- 둘러보기를 시작했거나 '다음에 보기'를 눌렀다는 사실은 브라우저에 남습니다(`localStorage`의
  `durume-journey-v1` 키). 이 키를 지우면 처음 오셨나요? 카드가 다시 뜹니다.

데모에서 바꾼 내용은 Node.js 프로세스 메모리에만 남으므로, 서버를 다시 켜면 처음 상태로 돌아갑니다.
실제 사용자 데이터나 운영 데이터에는 쓰지 마십시오.

## 로컬 데모와 Graph/Excel 모드

| 항목 | 로컬 데모 | Graph/Excel |
| --- | --- | --- |
| 서버 설정 | `DATA_MODE=demo` | `DATA_MODE=graph` |
| 데이터 원본 | `src/lib/demo-data.ts`의 프로세스 메모리 | 설정한 OneDrive workbook의 Excel 표 |
| 로그인 | 위쪽 데모 사용자 선택기 | Microsoft 로그인(`/api/auth/signin`) |
| 역할 | 데모 회원·관리자 선택 | workbook `Users`의 `role` |
| 바꾼 내용 보존 | 서버를 다시 켜면 초기화 | OneDrive workbook에 저장 |
| 오류가 나면 | 로컬 데모만 사용 | 오류를 돌려주며 데모로 저절로 바꾸지 않음 |

`NEXT_PUBLIC_DATA_MODE`는 화면 표시에만 쓰는 보조 값입니다. 권한과 데이터 원본은 서버의
`DATA_MODE`가 정합니다.

## OneDrive에서 Graph/Excel 모드 실행하기

아래에 나오는 표 이름과 환경 변수 이름은 실제 코드와 같습니다.

### 1. Workbook 만들고 OneDrive에 올리기

```powershell
npm run generate:workbook
```

기본으로 [`artifacts/3d-library-demo.xlsx`](artifacts/3d-library-demo.xlsx)가 만들어지며, 합성 도서
520권이 들어 있습니다. `Books` 표의 `titleKo`/`authorKo` 열은 한국어 화면에 보여 줄 제목과 저자
이름으로, 원래의 `title`/`author`와 함께 workbook에 저장됩니다. 이 파일을 로그인할 사용자의
OneDrive에 올립니다.

이 두 열은 예전 workbook과 호환되도록 선택 열로 두었습니다. 열이 없으면 한국어 화면에서도 영문
제목과 저자가 그대로 보이고, 열이 있으면 읽고 쓸 때 실제 표의 열 순서를 따라 번역 값도 지켜집니다.

권장하는 폴더 구성:

```text
OneDrive 루트
└── 3d-library
    └── 3d-library-demo.xlsx
```

Excel이나 OneDrive에서 파일이 열리는지 확인한 뒤에는 파일 이름과 폴더를 함부로 바꾸지 마십시오.
처음 실행할 때 이 파일은 OneDrive에 **실제 파일로 있어야** 하고, 로그인할 사용자에게 읽기·쓰기
권한이 있어야 합니다.

> 이 앱은 파일 경로를 환경 변수로 받지 않습니다. 대신 Graph URL에 쓰는
> `GRAPH_DRIVE_ID`와 `GRAPH_WORKBOOK_ITEM_ID`를 받습니다.

### 2. OneDrive 파일의 Graph drive/item ID 확인하기

1. [Microsoft Graph Explorer](https://developer.microsoft.com/graph/graph-explorer)를 엽니다.
2. 파일을 올린 Microsoft 계정으로 로그인하고, 그 계정의 OneDrive에 접근할 수 있는
   Microsoft Graph delegated 권한에 동의합니다.
3. 파일이 OneDrive 루트에 있으면 다음 `GET` 요청을 보냅니다.

   ```text
   https://graph.microsoft.com/v1.0/me/drive/root:/3d-library-demo.xlsx
   ```

   위의 권장 폴더 구성을 따랐다면 이렇게 요청합니다.

   ```text
   https://graph.microsoft.com/v1.0/me/drive/root:/3d-library/3d-library-demo.xlsx
   ```

4. 응답에서 다음 값을 확인합니다.

   ```json
   {
     "id": "<GRAPH_WORKBOOK_ITEM_ID로 사용할 파일 item ID>",
     "parentReference": {
       "driveId": "<GRAPH_DRIVE_ID로 사용할 drive ID>"
     }
   }
   ```

5. 경로에 공백이나 한글 파일 이름이 있으면 Graph URL 규칙에 따라 URL 인코딩합니다.
   식별자를 한 번 확인한 뒤에는 파일을 옮기거나 이름을 바꾸지 않는 편이 안전합니다.

확인한 `driveId`는 실제 Drive 식별자이고, 파일의 `id`는 Excel workbook item 식별자입니다.
사용자 ID, Excel 행 번호, 표 안 행의 `id`와는 다릅니다.

### 3. Microsoft Entra 앱 등록하기

1. Microsoft Entra 관리 센터에서 **App registrations > New registration**을 고릅니다.
2. 지원 계정 유형은 시험할 사용자와 파일 소유자에 맞춰 고릅니다.
   - 조직 OneDrive 계정만 쓸 때: 현재 조직의 단일 테넌트(권장)
   - 여러 조직이나 개인 Microsoft 계정까지 허용할 때: 두 계정 유형을 모두 포함하는 옵션
3. **Web** 플랫폼을 추가하고 정확한 redirect URI를 등록합니다.

   로컬 개발:

   ```text
   http://localhost:3000/api/auth/callback/azure-ad
   ```

   배포할 때는 실제 HTTPS 주소로 같은 경로를 추가합니다. 예:

   ```text
   https://library.example.com/api/auth/callback/azure-ad
   ```

4. 앱 등록의 **Certificates & secrets**에서 client secret을 만들고 **Value**를 따로 적어 둡니다.
   `AZURE_AD_CLIENT_SECRET`에는 Secret ID가 아니라 이 Value를 넣습니다.
5. **API permissions > Add a permission > Microsoft Graph > Delegated permissions**에서
   `Files.ReadWrite.All`과 `User.Read`를 추가합니다.
6. 로그인할 때는 다음 scope도 요청합니다.

   ```text
   openid profile email offline_access Files.ReadWrite.All User.Read
   ```

`Files.ReadWrite.All`은 로그인한 사용자가 접근할 수 있는 파일을 읽고 쓰게 해 주는 강한 권한입니다.
사용자 동의를 허용한 조직이면 로그인할 때 사용자가 직접 동의할 수 있습니다. 테넌트 정책이나
`Files.ReadWrite.All` 승인 정책으로 사용자 동의를 막아 둔 조직에서는 테넌트 관리자가
**Grant admin consent**를 실행해야 합니다. 이 저장소의 코드는 테넌트 동의를 대신 처리하지 않습니다.

### 4. `.env.local` 설정하기

다음은 OneDrive의 `3d-library/3d-library-demo.xlsx`를 쓰는 예입니다. ID와 secret 자리에는 예시 값이
아닌 실제 값을 넣어야 합니다.

```dotenv
DATA_MODE=graph
NEXT_PUBLIC_DATA_MODE=graph

NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=use-a-long-random-value-of-at-least-32-characters

AZURE_AD_CLIENT_ID=00000000-0000-0000-0000-000000000000
AZURE_AD_CLIENT_SECRET=<Entra client secret의 Value>
# 단일 테넌트 앱이면 Directory (tenant) ID를 넣습니다.
AZURE_AD_TENANT_ID=11111111-1111-1111-1111-111111111111

# 위 Graph GET 응답의 parentReference.driveId
GRAPH_DRIVE_ID=b!example-drive-id
# 위 Graph GET 응답의 id
GRAPH_WORKBOOK_ITEM_ID=01EXAMPLEFILEITEM
```

모든 변수와 기본값은 [`.env.example`](.env.example)에 있습니다.

- `DATA_MODE`: `demo` 또는 `graph`. 다른 값을 넣으면 데모로 처리합니다.
- `NEXT_PUBLIC_DATA_MODE`: 브라우저 표시용 `demo`/`graph`
- `NEXTAUTH_URL`: OAuth callback 주소를 만들 때 쓰는 앱의 외부 URL
- `NEXTAUTH_SECRET`: NextAuth 세션을 암호화하고 서명하는 비밀 값
- `AZURE_AD_CLIENT_ID`: Entra 앱의 Application (client) ID
- `AZURE_AD_CLIENT_SECRET`: Entra client secret의 **Value**
- `AZURE_AD_TENANT_ID`: Directory (tenant) ID, 또는 지원 계정 유형에 맞춰 `common`
- `GRAPH_DRIVE_ID`: Graph item 응답의 `parentReference.driveId`
- `GRAPH_WORKBOOK_ITEM_ID`: Graph item 응답의 파일 `id`

secret, access token, Graph ID를 소스에 커밋하지 마십시오. `.env.local`은 `.gitignore`에 들어 있습니다.

### 5. 첫 Graph 사용자 등록하기

Graph 모드에서는 workbook `Users` 표에 등록된 사용자만 앱을 쓸 수 있습니다. 처음 로그인하기 전에
OneDrive에서 workbook을 열어 `Users` 표를 고칩니다.

1. 로그인할 실제 이메일 주소로 새 행을 더하거나, 데모 행을 복사해 새 안정 `id`를 붙입니다. 예:

   ```text
   id: user-actual-admin-001
   version: 1
   authId: admin
   displayName: Library Admin
   email: library.admin@example.org
   role: admin
   ```

2. 적어도 한 명은 `role=admin`으로 등록합니다. 운영자가 회원 화면도 보려면 같은 방법으로
   `role=member` 행도 더합니다.
3. 앱은 `Users.authId`를 로그인 token의 `sub` 값과 견주고, 대소문자를 가리지 않고 `Users.email`도
   견줍니다. 처음 설정할 때는 **실제 계정의 이메일을 정확히 넣는 방법이 가장 쉽습니다**.
4. `id`는 표 안에서 하나뿐이어야 하고 바뀌지 않아야 합니다. `authId`나 email을 맞추려고 `id`에
   실제 Microsoft 계정 ID를 쓸 필요는 없습니다.
5. Excel에서 고친 내용을 저장하고, `npm run dev`로 개발 서버를 켠 뒤 `http://localhost:3000`을 엽니다.
6. 화면의 Microsoft 로그인 링크를 눌러 `/api/auth/signin`으로 로그인합니다. 실제 callback 경로는
   `/api/auth/callback/azure-ad`입니다.
7. 로그인한 뒤 `My library`(내 서재)에서 대출·예약과 알림을 확인합니다. `Admin desk`(사서실) 메뉴는
   workbook에서 `role=admin`인 사용자에게만 보이고, 회원 화면에는 나타나지 않습니다.
8. Graph/Excel 모드에서도 서버 API가 `role`을 다시 확인하므로, 회원이 관리자 요청을 직접 보내도
   HTTP 403으로 막힙니다.

## Excel에서 고치고 앱에서 확인하기

1. OneDrive에서 설정한 workbook을 Excel for the web으로 엽니다.
2. 예를 들어 `Books` 표의 `book-...` 행에서 `title`을 시험용 값으로 바꾸고 저장합니다.
   `id`와 `version`은 손대지 않습니다.
3. 앱 화면을 새로고침하면 `/api/library`가 workbook의 7개 표를 다시 읽습니다. 바꾼 제목이 검색에
   나와야 합니다.
4. 관리자 화면에서 다른 시험용 도서의 제목이나 서가 배치를 바꿉니다. 앱은 `/api/actions`를 거쳐
   Graph로 workbook의 행을 고칩니다.
5. OneDrive의 Excel 표를 새로고침하거나 다시 열어, 같은 행의 제목·`shelfId`·`bin`이 바뀌고
   `version`이 올라갔는지 확인합니다.
6. 회원으로 대출을 신청하고, 관리자 화면에서 승인한 뒤 `Loans.status`, `approvedAt`, `dueAt`,
   `version`이 workbook에 반영되는지 확인합니다.

앱과 Excel에서 함께 편집할 때는 같은 행을 오래 열어 두고 양쪽에서 고치지 마십시오. 앱은 안정 ID와
`version`으로 충돌을 검사하며, workbook의 버전이 예상과 다르면 HTTP 409 `CONFLICT`를 돌려줍니다.

## Workbook 표 계약

파일에는 아래 이름의 Excel 표와 정확한 머리글(header)이 있어야 합니다.

| 표 | 열 |
| --- | --- |
| `Books` | `id`, `version`, `title`, `author`, `year`, `ddc`, `kdc`, `classIndex`, `locationId`, `shelfId`, `bin`, `coverColor`, `demo` |
| `Shelves` | `id`, `version`, `name`, `locationId`, `zone`, `floor`, `capacity` |
| `Locations` | `id`, `version`, `name`, `floor`, `zone` |
| `Users` | `id`, `version`, `authId`, `displayName`, `email`, `role` |
| `Loans` | `id`, `version`, `bookId`, `userId`, `status`, `requestedAt`, `approvedAt`, `dueAt`, `returnedAt` |
| `Reservations` | `id`, `version`, `bookId`, `userId`, `status`, `createdAt` |
| `Settings` | `id`, `version`, `key`, `value` |

규칙:

- 표끼리의 관계는 언제나 `id`로 잇고, Excel 행 번호는 내부 구현에서만 씁니다.
- 각 표의 `id`는 바뀌지 않고 겹치지 않아야 합니다.
- `version`은 0 이상의 정수이며, 의미 있는 수정이 있을 때마다 올라갑니다.
- 날짜는 ISO 8601 UTC 문자열입니다.
- `Settings`에는 `key=schemaVersion`, `value=1`인 행이 있어야 합니다.
- 대출 상태: `requested`, `approved`, `overdue`, `return_requested`, `returned`, `rejected`
- 예약 상태: `waiting`, `ready`, `fulfilled`, `cancelled`
- 역할: `member`, `admin`
- 표·시트·머리글 이름을 바꾸거나, 새 관계를 행 번호로 저장하지 마십시오.

## 자주 만나는 오류

| 증상/API 코드 | 원인 | 대응 |
| --- | --- | --- |
| Graph `404`, 앱의 `GRAPH_ERROR` | `GRAPH_DRIVE_ID`/`GRAPH_WORKBOOK_ITEM_ID`가 다른 파일을 가리키거나 파일이 삭제·이동됨 | Graph GET 요청을 다시 보내 `driveId`와 `id`를 고쳐 넣고 서버를 다시 시작 |
| 로그인 사용자가 `Users`에 없음: HTTP 403 `FORBIDDEN` | `Users.authId`나 `email`이 실제 로그인 사용자와 맞지 않음 | workbook `Users`에 정확한 email을 더하고 `role`을 설정 |
| Graph HTTP 403, 앱의 `GRAPH_ERROR` | delegated permission, 파일 쓰기 권한, 테넌트 동의가 모자람 | Entra에서 `Files.ReadWrite.All`, `User.Read`와 동의 상태를 확인하고, OneDrive 파일 접근 권한을 확인 |
| HTTP 401 `AUTH_REQUIRED` | Microsoft 로그인 세션이나 Graph access token이 없음 | `/api/auth/signin`으로 다시 로그인 |
| HTTP 401 `AUTH_EXPIRED` | Graph access token이나 세션이 만료됨 | 로그아웃한 뒤 다시 로그인하고, Entra client secret이 만료되지 않았는지도 확인 |
| HTTP 422 `SCHEMA_ERROR` | 필수 표·머리글이 없거나 타입·관계가 틀림, `schemaVersion` 불일치 | 새로 만든 workbook을 기준으로 표와 열을 되살리고 `Settings.schemaVersion=1` 확인 |
| workbook·표 오류가 `GRAPH_ERROR`로 표시됨 | workbook이 `.xlsx`가 아니거나 Graph가 Excel 표를 알아보지 못함 | Excel에서 파일 형식과 `Books` 등 7개 표 이름을 확인 |
| HTTP 409 `CONFLICT` | 다른 사용자가 같은 행을 먼저 고쳐 `version`이 달라짐 | 앱을 새로고침한 뒤 다시 실행하고, 손으로 고칠 때 `version`을 낮추지 않음 |
| HTTP 409 `INVALID_STATE` | 이미 대출 중인 도서, 중복 신청, 잘못된 상태 전이나 서가·구역 조합 | 도서·대출·예약의 현재 상태를 확인하고 가능한 다음 동작만 실행 |

Graph 인증이 만료되거나 workbook을 불러오지 못해도 앱은 데모 모드로 저절로 바뀌지 않습니다.
데모 데이터에만 저장된 내용을 운영 파일에 저장했다고 착각하지 않도록 하려는 것입니다.

## 구조와 운영상의 한계

Repository 계약은 `src/lib/domain.ts`의 `LibraryRepository`입니다. 지금 있는 adapter는
`src/lib/repositories/local.ts`와 `src/lib/repositories/excel.ts` 두 가지입니다. 화면은 Graph를 직접
부르지 않고 `/api/library`, `/api/actions` 서버 경계를 거칩니다. 덕분에 나중에 SharePoint 목록
adapter를 붙일 자리가 있지만, 지금 버전에는 Excel↔SharePoint 실시간 동기화나 이중 기록(dual-write)이
없습니다.

Excel API는 데이터베이스 수준의 serializable transaction을 제공하지 않습니다. 지금 버전은 workbook
session 안에서 `version`을 다시 확인한 뒤 행을 고치지만, 사용량이 많은 곳에 배포한다면 트랜잭션을
지원하는 저장소로 adapter를 바꾸거나 서버 쪽 직렬화를 더해야 합니다.

실제로 배포할 때는 정확한 HTTPS callback을 등록하고, 환경 변수는 플랫폼의 secret 저장소에 두며,
`NEXTAUTH_SECRET`과 Entra client secret을 주기적으로 바꾸십시오.
